# 病理画像AI診断支援 (Pathology AI Assistant)

LLM+Agentで作成した、病理医向けのLinuxで動作するデスクトップアプリです。WSI（全切片画像）をはじめとする病理画像を
表示しながら、ローカルの OpenAI 互換 LLM エンドポイントに「所見」「鑑別診断」を
依頼したり、チャットでやり取りしたりできます。
*以下の説明もすべてLLMで作成されているのでご留意ください。適宜修正したいと思います。

## 機能

- **画像ビューア**
  - WSI (.svs / .ndpi / .mrxs / .bif / .vsi / .scn / ピラミッドtiff) は
    OpenSlide 経由でピラミッドレベルを生かした低メモリ表示
  - 通常画像 (png / jpg / bmp / tiff) も表示可
  - ドラッグ（左・中ボタン）でパン、ホイールでズーム（カーソル位置固定）、
    Shift+ホイールや横スクロールでもパン可、ダブルクリックで全体表示
  - `+` / `-` / `0` / 矢印キーでも操作可
- **LLM連携**
  - 「🩠 所見」「🧬 鑑別診断」ボタン → 定型プロンプトでLLMに依頼、結果をストリーミング表示。
    **入力欄にテキストがあれば補足指示として一緒に送信される**（例:「リンパ節検体」と入力して所見）
  - チャット欄での自由なやり取り（Enter送信、Shift+Enter改行）。
    「画像を添付」チェック中は自由入力の送信時にもビュー画像が添付される
  - **複数画像の添付**: 「＋ 画像…」ボタンで画像ファイルを複数枚選択して添付
    （Ctrl/Shiftで複数選択）。チャットパネル（表示欄・入力欄）への
    ドラッグ&ドロップでも追加可。サムネイル帯の「✕ 名前」で個別に解除。
    送信時に現在ビューの画像とまとめて送られ、テキストが空でも添付のみで送信可。
    添付画像は長辺1280pxに縮小してPNGで送信するため帯域を節約
  - **WSIからの複数スナップ撮影**: 「📷 スナップ追加」ボタンで現在ビューの
    範囲を添付に追加。パン・ズームを変えながら複数回押すと、低倍の全体像と
    高倍の部分像などを撮り溜めてまとめて送信できる。スナップにはおおよその
    実効倍率（対物倍率×ズーム）と画像全体の中での中心位置がラベルとして付き、
    LLMにも並び順ごとに注記される
  - **顕微鏡カメラ連携（Swiftcam SC1003）**: 「🎥 カメラ」ドックで
    接続された顕微鏡カメラのライブプレビューを表示し、「📷 スナップを添付」で
    顕微鏡の視野をそのままチャットの添付に追加できる（顕微鏡観察 → LLM相談を
    その場で行える）。プレビュー解像度（912×686 / 1832×1374 / 3664×2748）、
    露出時間、ゲインをパネルから変更でき、「💾 保存…」でPNG保存も可能。
    「フル解像度で撮る」チェックで最高解像度（3664×2748）のスチルを撮影
    （プレビューが一時的に止まる数秒を要する）。カメラスナップはビューアの
    スナップと同じ要領でまとめて送信できる。ドックを閉じるとカメラの占有を
    解放する
  - **WSIファイルの直接添付**: 「＋ 画像…」やドロップで .svs / .ndpi / .mrxs /
    .bif / .vsi / .scn を渡すと OpenSlide で全体像（低倍サムネイル）を生成して
    添付する（OpenSlide未導入環境ではスキップして通知）。ピラミッドtiffも
    QImageで読めない場合はOpenSlide経由で添付する
  - **臨床情報欄（任意）**: 部位・年齢性別・備考を入力すると所見/鑑別/チャットのプロンプトに自動で含まれる
    （所見・鑑別ボタンはプロンプト本文に埋め込み、チャットは送信毎に最新の値を
    systemメッセージ経由で注入。表示される履歴は本文のみで簡潔のまま）
  - **モデル切替ドロップダウン**（ツールバー）: ハーネスで登録したモデルID
    (`~/.dsh/profiles/web/cordis.patch.yml`) とエンドポイントの一覧 (`/v1/models`)、
    およびアプリ組み込みの追加モデル (`config.py` の `EXTRA_MODEL_IDS`。
    ビジョン対応の `unsloth/DeepSeek-V4-Flash-Vision-Exp-GGUF:UD-IQ2_XXS` など)
    をマージして選択可。🔄ボタンで再取得。選択は `settings.json` に保存
  - モデルIDの表記ゆれ (`unsloth/` 接頭辞・`:量子化` 接尾辞の有無) は自動でリトライ解決
  - 「画像を添付」チェックで現在のビュー画像をLLMへ送信（ビジョン対応モデルのみ有効）
  - 設定ダイアログ（エンドポイントURL・モデル・APIキー・temperature・max_tokens）+ 接続テスト
- **症例管理**
  - 自由メモ欄 + 臨床情報欄（自動保存）
  - 症例（画像パス・メモ・臨床情報・チャット履歴）を JSON として `~/.pathology_app/cases/` に保存
  - チャット履歴（自由チャット・所見・鑑別の全やり取り）も自動保存の対象
  - **送信済み添付のPNG保存**: 送信のたびに添付画像（ファイル添付・スナップ・
    カメラスナップ・「画像を添付」チェックのビュー画像）を
    `~/.pathology_app/attachments/{症例ID}_{日時}_{連番}_{ラベル}.png` として
    保存し、症例JSONには**パス参照だけ**を記録する（JSONの肥大化を防止、
    画像をファイルマネージャから直接開ける）。LLMへの送信時は保存済みPNGを
    再読み込みしてbase64 data URLへ組み立てる
  - **履歴でも画像が見える**: 過去の症例を開くと、チャット欄に送信済み添付が
    サムネイル（長辺260px）で本文の下に表示される。旧形式（base64埋め込み）の
    履歴JSONもそのまま表示可
  - **履歴パネルの「保存済み添付」一覧**: 現在の症例で送信済みの添付画像を
    サムネイル付き（64px）で送信順に一覧表示。ダブルクリックで既定の
    ビューアで開く。ファイルが欠損しているものは「(ファイルなし)」と表示
  - **旧JSONの移行ツール**: `tools/migrate_attachments.py` — 既存の症例JSONに
    埋め込まれたbase64画像を attachments/ へPNG抽出し、JSONをパス参照に
    書き直す（元JSONは `~/.pathology_app/backup/cases_{日時}/` にバックアップ）。
    アプリを閉じてから `--write` を付けて実行
  - 履歴パネルは**作成順（新しい順）で固定**。クリックや再保存でも順番は変わらない
  - 履歴パネルからワンクリック呼び出し・削除
  - **名前変更**: 「名前変更」ボタンまたは履歴右クリックメニューで症例タイトルを
    変更できる（変更済みタイトルは自動生成の上書き対象から外す）
  - **タイトル自動生成**: 「(無題)」の症例には最初にローカル即時タイトル（画像
    ファイル名 → なければ最初のユーザー発言から抽出）を付け、最初のLLM応答後に
    内容に即したタイトル（20字程度）へLLMで上書きする。手動リネーム後の症例は
    自動生成しない

## 必要なもの

- Python 3.10+
- OpenSlide（WSIを読む場合）: `conda install -y -c conda-forge openslide`
- Pythonパッケージ: `pip install -r requirements.txt`
- OpenAI互換のLLMエンドポイント（既定はこの環境の unsloth ローカルサーバ）
- 顕微鏡カメラ機能（任意）: Swift Imaging 3.0 同梱のSDK
  `/usr/local/SwiftImaging3.0/libswiftcam.so`（ToupTek互換ABI）。無い環境でも
  アプリ本体はカメラドックなしで起動する。代替パスは環境変数
  `PATHOLOGY_SWIFTCAM_LIB` で指定できる

## 起動

```bash
./run.sh
# または
python pathology_app/main.py
```

初回起動時に `~/.local/share/applications/pathology-app.desktop` を自動生成します。
GNOMEのドック (タスクバー) では日本語アプリ名「病理画像AI診断支援」とアプリアイコンで
表示されます (WM_CLASSはASCIIの `pathology_app` にしているため、ドック側の
Latin-1解釈によるアプリ名の文字化けが起きません)。

## APIキーの扱い

優先順で解決します:

1. 設定ダイアログで入力したキー（平文で `~/.pathology_app/settings.json` に保存）
2. 環境変数（既定: `LOCAL_TALISCALE_API_KEY`）
3. DeepSeek Harnessのクレデンシャル `~/.dsh/.credentials.yaml` の refs

## 注意事項

- LLMの出力は参考情報です。診断の最終判断は必ず病理医が行ってください。
- 添付画像はビジョン対応モデルでないとエラーになることがあります
  （例: GLMテキストモデルでは非対応。ビジョンモデルを選んでください）。
- WSIのメタ情報（ファイル名・解像度・対物倍率）と臨床情報はプロンプトに自動で含まれます。

## トラブルシューティング

### 日本語が入力できない (fcitx5環境)

pip版PySide6にはfcitx入力プラグインが含まれないため、`QT_IM_MODULE=fcitx` のままだと
Qtがサイレントに入力メソッドなしにフォールバックします。本アプリは起動時にこれを検出し、
自動的に `QT_IM_MODULE=ibus` へ切り替えます（fcitx5のIBus互換D-Busインターフェース経由）。

自動切り替えでも入力できない場合:

- fcitx5の設定で「追加モジュール → IBus」が有効か確認する
- 手動で `QT_IM_MODULE=ibus ./run.sh` として起動する
- システムの `fcitx5-qt6` を使う方法もあるが、PySide6同梱Qt (6.12) とシステムQt (6.4系) の
  バージョン不一致によりプラグインが読み込めないため非推奨

### WSIのパン表示がおかしい場合

`smoke_test.py` にリージョン計算の回帰テストがあります。実行して `SMOKE_OK` が出るか確認してください。

### カメラパネルに「見つかりません」「開けませんでした」と出る場合

- Swift Imaging 3.0 など別アプリがカメラを占有していると開けません。先にその
  アプリを閉じてからカメラパネルを開いてください（逆に本アプリでライブを
  止めてカメラの占有を解放するには、ドックを閉じるか「🎥 ライブ」を解除します）
- USB3ポート・ケーブルの接触を確認（SC1003はUSB3専用。USB2ポートでは
  映像が届かないことがあります）

### カメラの映像が真っ暗な場合

- 接続された顕微鏡の照明（光源）が入っているか確認してください。消灯時は
  全体が黒（平均輝度≈0）になります
- 暗い視野ではパネルの「露出」を大きく（例: 100,000 µs 以上）、または
  「ゲイン」を上げると明るくなります。明るすぎる（白飛び）場合は露出を
  小さくします
- スナップが白飛び・暗いままであれば露出を変えてから「📷 スナップを添付」
